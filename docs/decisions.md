# 底座选型和审查记录

## 开工前确认的问题

| 评审稿缺口 | 本轮决定 | 后续门槛 |
|---|---|---|
| 有租户列和 RLS，组织、角色及数据库运行账号仍缺实现 | 同租户组织授权、明确应用角色、服务端授权和数据库权限共同落地 | 真实身份接入、撤权策略和实际连接池验收 |
| 场景版本依赖应用约定 | 已发布场景单独建表并限制修改，受理任务固定版本 | 后续为规则、因子、边界、证据、计算和报告分别定义冻结与更正 |
| 受理、审批和成功审计缺事务契约 | 受理状态转换、预期修订、创建人与复核人分离，成功审计与更新同事务 | 独立 PostgreSQL 上并发争用与故障恢复 |
| 原型将多种界面入口放在一起 | 客户、专业、管理命令分开，使用同一组租户和组织授权 | UI 团队分别设计入口，接入经认证的服务 |

## 开源实现对比

核对日期为 2026-11-05。依赖通过锁文件固定。

| 候选 | 已验证的做法、许可证和代价 | 决定 |
|---|---|---|
| [node-postgres](https://github.com/brianc/node-postgres) | MIT。使用成熟连接池及参数化查询。事务须占用同一连接，回滚后释放 | 采用 pg 作为真实 PostgreSQL 的运行适配器 |
| [Electric PGlite](https://github.com/electric-sql/pglite) | Apache-2.0 或 PostgreSQL 许可证。WebAssembly 引擎可执行 PostgreSQL SQL，单连接限制意味着不能替代真实的并发测试 | 作为测试依赖，避免开发环境需要先安装数据库服务器 |
| [golang-migrate](https://github.com/golang-migrate/migrate) | MIT。用数据库锁序列化迁移，并记录版本及失败状态。作为额外 CLI 或服务镜像部署 | 借鉴迁移顺序及数据库锁；首片只运行事务型 SQL，以少量代码记录校验和，生产工具随部署方式再定 |

没有从第三方仓库复制业务源码。常规失败由事务回滚和明确错误处理覆盖。新增特殊防御前按工程规则说明触发概率、影响和复杂度。
