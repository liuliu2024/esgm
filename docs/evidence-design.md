# 证据管理详细设计

下一切片从补正文本扩展到材料登记。受理人与复核人需要确认用了哪份原件、它支持哪个版本、是否经过安全检查。该能力先独立于碳算法和报告生成。

## E01 材料清单登记

| 动作 | 权限及条件 | 请求与结果 |
|---|---|---|
| 登记材料 | 客户本人，受理为草稿或退回 | `POST /v1/customer/cases/:id/evidence`，提交 `orgId, title, sourceDescription`，返回 201 登记项 |
| 查看清单 | 企业看本人，专业人员看授权组织已进入复核的受理 | `GET /v1/{customer|professional}/cases/:id/evidence?orgId=…`，返回 `{items}`，按创建时间、ID 排序 |

标题为 1–200 字符，来源说明为 1–1000 字符。登记返回材料 ID、受理及组织 ID、登记者、标题、来源说明、时间和固定状态 `pending_file`（待补文件）。拒绝外部传入核验状态或存储地址。不存在或不可见返回 404，缺组织角色返回 403，提交或批准后尝试登记返回 409。

登记行以租户、组织及任务的复合外键绑定，并受任务范围和身份约束。原登记只读，补录另建记录。保留登记人和时间。当前不改变受理修订或提交审计。界面接入时使用“材料清单”和“待补文件”文案。

## 需求及依据

原报告第 4、8 章要求结果可追溯到版本和原始证据。生态环境部年度工作通知和钢铁、水泥、铝冶炼行业相关政策问答可作为数据质量与存证场景参考。实际适用性按企业、行业及年份复核。 [年度工作通知](https://www.mee.gov.cn/xxgk2018/xxgk/xxgk06/202602/t20260209_1143900.html) · [数据质量政策问答](https://www.mee.gov.cn/ywdt/zbft/202511/t20251119_1134197.shtml)

本轮在公众号公开索引中查找了月度存证和数据质量资料，未找到足以独立支撑规则配置的来源。保留政策机关原文和适用条件作为发布依据。

## 数据及动作

- 凭证元数据保存租户、组织、对象存储键和版本、校验摘要、媒体类型、字节数、上传者与时间。文件名仅用于显示。可被权限隔离的材料状态为待检查、可引用、被拒绝。
- 证据引用绑定任务及对应提交修订、定位与用途。客户可补充材料，复核人读取获授权的版本。后续修订追加新引用，旧版仍能按原始权限策略回看。
- 真实上传、扫描及存储配置单独接入，界面明确区分已登记与可使用。上传限制、内容校验和文件访问控制参考 [OWASP File Upload Cheat Sheet](https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/File_Upload_Cheat_Sheet.md)。此处采用设计原则，未引入外部业务源码。

## 放行测试

登记两份材料并将其中一份绑定到补正版本。复核人能在对应修订看到关联。未完成检查的材料不能进入正式引用。跨租户和同租户异组织访问被拒绝。新材料不会覆盖旧引用。测试用文件与生产存储配置分开。
