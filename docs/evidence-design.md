# 证据管理详细设计

下一切片从补正文本扩展到材料登记。受理人与复核人需要确认用了哪份原件、它支持哪个版本、是否经过安全检查。该能力先独立于碳算法和报告生成。

## E01 材料清单登记

| 动作 | 权限及条件 | 请求与结果 |
|---|---|---|
| 登记材料 | 客户本人，受理为草稿或退回 | `POST /v1/customer/cases/:id/evidence`，提交 `orgId, title, sourceDescription`，返回 201 登记项 |
| 查看清单 | 企业看本人，专业人员看授权组织已进入复核的受理 | `GET /v1/{customer|professional}/cases/:id/evidence?orgId=…`，返回 `{items}`，按创建时间、ID 排序 |

标题为 1–200 字符，来源说明为 1–1000 字符。登记返回材料 ID、受理及组织 ID、登记者、标题、来源说明、时间和固定状态 `pending_file`（待补文件）。拒绝外部传入核验状态或存储地址。不存在或不可见返回 404，缺组织角色返回 403，提交或批准后尝试登记返回 409。

登记行以租户、组织及任务的复合外键绑定，并受任务范围和身份约束。原登记只读，补录另建记录。保留登记人和时间。当前不改变受理修订或提交审计。界面接入时使用“材料清单”和“待补文件”文案。

## E02a 本地演示隔离接收

E01 材料清单登记已对应 GitHub 提交 `e39ada…`。E02a 在本地演示环境增加文件接收，接收结果仅供后续检查。此阶段从“待补文件”进入“待检查”。正式扫描、核验结论与提交版本引用另列验收。

| 项目 | 设计与验收 |
|---|---|
| 接收范围 | 仅接收 PDF、PNG，文件字节数上限 5 MiB。测试有效样本、空文件、超限和内容与媒体类型不符。类型检查只判断接收条件 |
| 操作权限 | 仅客户本人可给获授权的草稿或退回任务附加文件。检查他人任务、已提交或批准任务、跨租户、同租户异组织及撤权后的拒绝 |
| 完整性与存放 | 服务按实际接收的字节计算 SHA-256，生成内部存储定位并写入本地隔离区。客户选择的文件名留在本机。核对返回状态、文件大小及摘要与实际字节一致 |
| 不可变 | 同一材料登记只能成功接收一份。拒绝原地修改、替换及重复接收。再次接收失败时检查先前文件、摘要和记录保持原状 |
| 失败回滚 | 隔离写入失败时回滚业务事务，由存储适配器清理本次临时文件。测试失败注入并确认无成功接收记录。演示库和隔离目录在正常关闭时一并清理。文件落盘后数据库提交未确认时的逐对象对账、进程崩溃清理和恢复属于正式存储放行项；正式流程先核对已提交记录再清理孤立文件 |
| 使用边界 | 接收记录为待检查，不生成核验结果，也不可作为正式引用。界面或响应不得把接收显示为核验通过 |

开发对齐接收与查询契约、迁移、演示样本和可复现命令。数据库岗负责归属、状态与唯一性约束。服务岗负责内容接收、摘要与隔离写入和失败清理。由 QC 检查边界，两位测试分别复跑数据库与接口用例。完成后直接安排下一可验收切片。

## 后续正式扫描及版本引用

### 扫描接入选型

私有化候选为独立 ClamAV 守护进程，使用标准 `INSTREAM` 协议交给隔离扫描服务处理。托管部署候选为与实际对象存储匹配的托管扫描。开源方案依赖签名更新、网络隔离和守护进程可用性，托管方案依赖云权限、地域及事件投递。首期保留扫描服务边界，依部署选择供应方。比较来源：[ClamAV 许可证与依赖](https://github.com/Cisco-Talos/clamav/blob/main/README.md) · [ClamD 协议与限制](https://docs.clamav.net/manual/Usage/ClamdProtocol.html) · [GuardDuty 扫描结果与失败状态](https://docs.aws.amazon.com/guardduty/latest/ug/monitoring-malware-protection-s3-scans-gdu.html)。

扫描工作进程依据不可变接收 ID 找到隔离对象，先重新比对字节数和 SHA-256，再提交扫描。只接受可信扫描进程的结果，记录引擎、签名版本、时间和对象摘要。未响应、超限、扫描错误、读取失败和摘要不一致均保持不可引用。扫描通过只表示文件满足接入检查，专业复核仍按业务证据要求进行。

扫描进程通过独立 PostgreSQL 登录角色继承 `carbon_scanner`，与应用连接隔离。应用角色可在原收件权限内读取结果，不能写入。扫描进程写入每个收件的首次终态，再次处理已完成的收件时返回原结果。扫描失败保留待检查。当前演示继续展示待检查，扫描状态和版本选择由后续交互切片接入。

正式部署验收须使用专用私有 ClamD 端点，将 `StreamMaxLength` 覆盖接收上限，并开启 `AlertExceedsMax` 及验证适用引擎限制。验证干净样本、标准测试病毒样本和超限场景。签名版本由扫描前的守护进程响应记录，若部署要求严格绑定扫描所用签名，须在验收时核对签名更新的运行方式。端点限制及配置以 [ClamD 配置样例](https://github.com/Cisco-Talos/clamav/blob/main/etc/clamd.conf.sample) 为准。

### E02b 可信检查与 E03 引用交接

| 用例 | 详细约束 | 验收 |
|---|---|---|
| 可信扫描结果 | 独立扫描进程身份读取指定的隔离收件。收件 ID、租户、组织、材料及 SHA-256 对齐，追加可信结果，记录引擎、签名版本和时间 | 客户与复核接口不能写入结果。错误、跳过、未检查和摘要不一致不得转为可引用 |
| 扫描服务接入 | 先通过受信本机或私有网络运行标准扫描，业务核心只识别验收通过的结果 | 模拟协议测试用于覆盖状态转换，真正扫描结果须由目标部署的实际扫描器用安全测试样本验证 |
| 修订绑定 | 仅有可信通过结果的收件可引用。客户提交时将所选证据与该次提交修订一并固定，专业人员查看同版本证据 | 新提交创建新引用，旧版本可复查。跨任务材料和待检查收件被拒绝 |
| 正式存储 | 按实际对象版本核对摘要、状态和权限，隔离文件无直接公开入口 | 验证权限撤销、对象替换检测、未确认提交对账和备份恢复 |

### E03 提交修订的接口及验收

| 接口 | 约定 |
|---|---|
| `POST /v1/customer/cases/:id/submit` 和 `POST /v1/customer/cases/:id/resubmit` | 可选 `evidenceIds` 为本次引用的材料 ID 数组，省略或空数组表示该修订无引用。入口验证 UUID 和重复项。若引用有不可用项，整个提交返回 409，任务状态、修订及审计均保持原状 |
| `GET /v1/{customer\|professional}/cases/:id/revisions/:revision/evidence?orgId=…` | 沿用对应角色的受理可见性，返回指定已提交修订的 `{items}`。既有提交无引用时返回空数组，非提交修订或不可见任务返回 404 |

提交事务从可信通过结果解析收件 ID 与摘要。版本引用和状态转换在同一事务提交。关联项保存原材料登记、收件和扫描结果的身份，业务底座可以回溯至具体字节。存储定位留在服务端。若客户只想补交说明，可保持引用为空，也可明确选用仍可引用的旧材料。专业人员审查所选修订，历史引用仍按原范围读取。

验收先创建一份待检查材料并尝试提交，核对失败后版本和审计未变。待可信结果通过再提交，专业端读到准确材料。退回后提交另一份材料，旧修订读取仍一致。补测同租户异组织、跨租户、其他任务材料、旧客户端省略字段、重复 ID，以及两个并行提交已有的版本冲突语义。

### 数据及动作

- 凭证元数据保存租户、组织、对象存储键和版本、校验摘要、媒体类型、字节数、上传者与时间。文件名仅用于显示。可被权限隔离的材料状态为待检查、可引用、被拒绝。
- 证据引用绑定任务及对应提交修订、定位与用途。客户可补充材料，复核人读取获授权的版本。后续修订追加新引用，旧版仍能按原始权限策略回看。
- 真实上传、扫描及存储配置单独接入，界面明确区分已登记与可使用。上传限制、内容校验和文件访问控制参考 [OWASP File Upload Cheat Sheet](https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/File_Upload_Cheat_Sheet.md)。此处采用设计原则，未引入外部业务源码。

### 放行测试

登记两份材料并将其中一份绑定到补正版本。复核人能在对应修订看到关联。未完成检查的材料不能进入正式引用。跨租户和同租户异组织访问被拒绝。新材料不会覆盖旧引用。测试用文件与生产存储配置分开。
