# 三端界面交接

| 页面 | 工作重点 | 显示的主操作 |
|---|---|---|
| 企业工作台 | 新建受理和处理自己的退回任务 | 草稿提交、退回补正及重提 |
| 专业作业台 | 查看有权处理的复核队列 | 批准或填写理由退回 |
| 组织审计 | 查阅状态、版本和对应原因 | 翻看本组织的审计记录 |

客户前台从业务和任务出发。企业工作台不出现复核、管理、技术设计或角色切换。专业及管理由独立入口打开，界面按各自 API 权限展示。列表任务名称可进入详情，状态在同一行可读。详情强调一项当前动作，历史可按需查看。错误与表单相关时贴近对应动作。状态冲突后刷新当前任务，保留用户尚未提交的文字。

参考 [GOV.UK Task List](https://design-system.service.gov.uk/components/task-list/) 的任务名称与明确状态配对。评估了 [GOV.UK Frontend](https://github.com/alphagov/govuk-frontend) 的 MIT 代码许可、维护版本和已知问题记录。本轮借鉴状态结构，沿用本项目视觉规则和原生浏览器控件。

本地演示三端访问同一个真实服务实例和临时数据库。启动只监听本机，合成角色由演示进程提供。生产接入需经认证映射、正式运行账号和环境放行。

## 专业案卷

- 队列负责找任务，选中任务后进入全宽案卷。返回时恢复原任务焦点，便于继续处理队列。
- 案卷按材料与范围、规则与核算、报告复核、受理决定切换。名称、状态和任务版本在案卷顶部，材料和核算共用提交版本。受理决定和报告复核使用各自的表单。
- 正式版验收覆盖桌面与窄屏、键盘进入和返回、长案卷、空材料与缺项状态、历史版本切换和退回草稿恢复。核心动作由布局、名称和状态识别。
