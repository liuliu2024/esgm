# 碳有据首个底座纵切需求

**评审状态**　开工与验收基线  
**适用范围**　空库研发环境中的受理、提交、独立复核和审计

## 1 本阶段交付

验证一个经过身份识别的企业用户能在授权组织下保存业务受理记录并提交。另一位获得复核授权的人员可以批准或退回。系统可以说明使用了哪个场景版本、谁在什么组织范围内执行了哪个动作，以及该动作是否成功提交。

以组织碳盘查受理或采购方报告需求受理为演示任务。记录具体对象、用途和需求描述。首片的“批准”表示**受理信息通过复核**，对应后续业务任务可继续办理。碳计算结果、核查结论、认证、报告签发及外发属于后续用例。

## 2 三端边界和授权

| 端 | 本阶段职责 | 操作权限 |
|---|---|---|
| 企业前台 | 录入受理信息、提交、查看办理状态及退回原因 | 发起人在所属授权组织创建和提交。组织内哪些人员可查看应由明确的查看权限决定 |
| 专业作业台 | 查看待审提交、批准或退回并留痕 | 复核人需要该组织的复核授权，且身份与本次提交人分离。发起人兼有复核角色时仍受独立性约束 |
| 管理端 | 维护组织、授权和已发布的场景配置，按授权审阅审计 | 管理权限独立于业务发起和复核权限。首片可通过受控初始化创建配置和授权，管理界面及授权变更 API 后续接入 |

三端可以接入同一业务服务，各自获得对应动作的权限。界面路由和按钮只负责引导。服务端从可信身份上下文取得操作者，从显式授权确定可操作的租户、组织及动作。客户端选择工作空间或传入组织 ID 只表达意图，仍需服务端验证。数据库以租户隔离和复合引用约束补强，组织和动作权限在服务用例中逐一落实。

## 3 受理和复核

1. **保存草稿。** 绑定租户、组织、操作者和明确的已发布场景版本。保存经过字段校验的受理内容。新场景版本发布后，历史草稿和已提交事项仍引用原版本。业务需要重新评估时按明确的变更流程办理。
2. **提交。** 校验操作者、当前组织授权、必填项和状态。提交固定本次受理快照。已提交记录不得原地改写，后续更正应形成可追溯的新修订。
3. **批准或退回。** 只处理当前已提交记录。退回须记录理由，批准须能定位当次提交。采用事务内状态约束及冲突检测，重复、过期或并发请求只允许合法状态转换成功。退回后重新编辑与提交若未实现，状态与理由仍须可查，下一片补齐修订入口。
4. **审计。** 记录租户、组织、受理记录、动作、操作者、时间及结果状态。业务变更与成功审计同事务提交，审计对普通业务主体只追加。拒绝、验证失败及运行错误可进入独立安全日志，防止与成功审计混淆。日志字段避免复写完整的敏感受理内容。

## 4 首片验收

采用两个租户，第一租户内至少两个组织。准备发起人、独立复核人、只具备管理权限的人和无权主体。至少一个人可同时具备发起与复核授权，用于验证自审限制。

| ID | 验收场景 | 合格证据 |
|---|---|---|
| F01 | 发起人创建草稿、提交，独立复核人批准 | 实际数据库记录与返回状态一致。每次成功变更有对应审计 |
| F02 | 第二条记录被独立复核人退回 | 记录状态、理由、审计和原提交仍可定位 |
| F03 | 另一租户、同租户另一组织或撤权主体访问已知记录 ID | 读写均拒绝且不泄露受理内容。权限只够管理时无法提交或复核 |
| F04 | 具有双角色的发起人尝试审核自己提交的事项 | 拒绝操作，受理记录、审核和成功审计保持原状 |
| F05 | 重复提交、已处理记录再次复核、请求版本过期 | 拒绝非法状态推进。真并发下验证只产生一次有效复核；单连接测试无法替代此项 |
| F06 | 已发布场景新增版本，尝试改写已提交内容 | 历史记录仍引用原场景及受理快照。普通运行角色无法覆写或删除审计 |
| F07 | 缺失租户上下文、事务异常以及切换租户后复用连接 | 缺失时不返回受保护数据；异常回滚无业务或审计残留；连接复用不沿用上一次租户上下文 |
| F08 | 空库迁移和再次执行迁移入口 | 空库可复现安装。已执行迁移可识别。测试报告区分真实数据库验证、应用验证与尚未完成的验收 |

## 5 排期和生产放行

| 优先级 | 工作 |
|---|---|
| 当前片 | 可信身份接入契约、租户与组织授权、受理和复核状态、版本引用、追加审计及可执行迁移 |
| 下一片 | 受理修订与续办、企业前台和专业作业台接入、管理端授权配置、证据对象存储和可追溯下载 |
| 专项片 | 确定性计算和复算、报告签发、披露审批与外发、AI 辅助、行业方法包 |

**试点上线条件**　接入正式身份源并验证身份映射与撤权，使用真实 PostgreSQL 实例完成非表所有者角色、连接池和并发事务验证，完成迁移、备份恢复、日志留存和运行权限演练。工作区演示身份、嵌入式数据库验证和代码审查分别记录。任何异租户可见、越权写入、自审、重复复核或审计不一致均阻断试点上线。
