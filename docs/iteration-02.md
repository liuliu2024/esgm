# 碳有据迭代二底座续办与前台交接

## 阶段 A 受理续办

客户在授权组织的本人任务列表中打开退回记录，查看原因与当前修订，填写补正说明并重新提交。独立复核人可批准或再次退回。原始用途保持可追溯，每轮退回理由、补正说明、操作者、修订和审计均可定位。批准仍表示受理信息通过。

| 验收项 | 合格证据 |
|---|---|
| A01 任务列表 | 只返回当前主体在有权组织的本人任务。客户可识别状态和下一步。换租户、换组织、换主体或撤权后的请求不泄露记录 |
| A02 退回与补正 | 从退回详情可查具体原因和修订。补正说明必填，原始用途和已提交历史保留 |
| A03 重提与复核 | 第一次退回后重提，再由独立复核人处理。再次退回和补正后仍能按顺序查到每轮记录。具有双角色的客户无法自审 |
| A04 状态和审计 | 过期修订或重复动作不能再次推进。业务与对应审计同事务，失败不留下补正、状态或成功审计 |
| A05 迁移回归 | 空库和已有上一版数据的环境均能升级。现有接口与已提交数据仍可读取。数据库单连接验证与真实多连接验收分开记录 |

| 责任岗 | 阶段 A 工作及交接 |
|---|---|
| 高级需求分析 | 锁定补正业务口径、可见性和状态。补正与正式报告修改是不同用例 |
| 资深数据库开发 | 增量迁移、隔离与历史约束、审计。交接表字段、动作、迁移步骤及回滚边界 |
| 资深服务开发 | 列表、详情、补正重提和复核的服务用例。交接路径、输入、状态、修订、错误语义及运行样例 |
| 独立 QC | 核对上述验收、契约、工程规则和原流程回归，明确阻断项 |
| 数据库测试 | 独立执行迁移、租户与组织隔离、历史保留、状态约束及事务审计测试 |
| 接口测试 | 通过服务入口验证两轮处理、撤权、跨组织、同人自审和过期修订。核对返回状态与实际数据库结果 |
| 项目管理 | 管理变更与依赖，收集验证证据，安排修复与复测。根代理负责运行环境、集成和交付 |

同时最多三个子 Agent。需求和两位开发先收口契约并交付实现，空出的席位由 QC 和两位测试接力。原岗位处理缺陷，测试复跑，QC 复核后由项目管理岗确认交接。更新先核对用户操作、开发契约和 Agent 协作。未确认的低概率防护另提需求，已约定的权限、状态与事务约束按主流程验收。

## 阶段 B 前台团队接力

接续前提供阶段 A 的可运行服务、演示账号角色、输入输出、状态转换、权限矩阵和失败示例。前台先以同一笔示例受理走通三端，用实际服务结果检查下一步动作和状态。

| 界面 | 首批范围 |
|---|---|
| 企业工作台 | 本人任务列表、退回原因、补正说明、重新提交及历史。当前状态与可执行动作可见 |
| 专业复核 | 待审任务、各轮材料、批准或退回、理由和反馈。按授权显示操作 |
| 管理入口 | 单独进入管理与审计界面，按现有授权查询可见范围。后台配置、全量授权管理另排 |

页面按客户、专业和管理职责分离。演示身份切换与评审入口放在演示工具区。删减可从上下文理解的解释、标语和次要标签。用页面结构说明步骤与责任，保留退回原因、风险和权限所需信息。范围限受理续办演示；碳核算、核查结论、报告签发与其他业务另立需求。

## 交付与生产验证

阶段 A 可交付条件为 A01–A05 有实际执行证据、阻断缺陷关闭，且可演示两轮退回补正。阶段 B 接力后继续开发并演示真实服务交互，报告用于记录进度与缺口。

生产试点仍需正式身份接入、授权撤销与身份映射、真实 PostgreSQL 非所有者运行角色、连接池隔离与并发事务，以及迁移和备份恢复实测。演示通过、源代码提交与生产放行分别记录。

### UI 验收清单

- 以同一笔受理记录走真实服务：客户查退回原因、补正重提，专业人员再次复核，管理端查询获授权审计。展示原始用途、每轮补正与结果，刷新后以服务状态为准。
- 企业前台、专业复核和管理入口各自可辨识，当前身份和授权决定可见任务及操作。客户看不到评审工具或内部配置入口。演示身份切换在独立工具区。
- 检查空列表、加载、失败、撤权、过期修订及成功后状态。发现前台与服务契约不同，记录复现及责任岗并复验，避免界面提前显示操作成功。
- 检查说明文字、操作层级、返回接续和键盘操作。验收记录应区分界面检查、真实服务演示及尚待验证的生产身份与数据库环境。

### 下一切片开工清单

以 [证据管理详细设计草案](./evidence-design.md) 为起点，先锁定材料登记和修订引用的最小契约，再分派数据库、服务、QC 与测试岗位。

- 确认租户、组织、任务、提交修订和操作者的归属与授权，明确跨租户、同租户异组织及撤权后的访问结果。
- 固定材料元数据、待检查／可引用／被拒绝状态、引用用途和定位。仅安全检查通过的材料允许正式引用，绑定旧修订的引用保留。
- 确认增量迁移、服务入口、审计事件和演示夹具。验收从登记两份材料、绑定一份到补正修订开始，包含未检查材料拒绝、权限拒绝和历史保留。
- 明确元数据登记、真实上传、文件扫描和对象存储的交接边界。生产存储和安全能力通过独立实测后再放行。
